走进大模型（五）——PagedAttention

发表于 2025-08-20 分类于 llm技术 阅读次数： Valine：
本文字数： 2.5k 阅读时长 ≈ 2 分钟

这一篇将以该论文为基础：[2309.06180] Efficient Memory Management for Large Language Model Serving with PagedAttention。讲PagedAttention及KV cache在vLLM中的优化，PagedAttention是应用于vLLM 中的一项用于增加服务吞吐量的重要技术。在讲PagedAttention之前，会简单说说KV cache是什么。

KV cache

KV cache顾名思义，就是将大模型在进行注意力计算时，用到的K和V矩阵进行缓存。这样在下次用到时，可以直接读取，而不用重新计算。计算注意力时用到了三个矩阵，为什么只缓存KV，而不存Q。假设序列总长度为T，QKV都为T行k列的矩阵，简而言之，是因为在计算序列t位置时，只有第t行的Q向量参与了计算，而从1到t行的KV向量都会参与计算，因此，在生成新的token时，上一次的Q用不上，而之前的KV可以复用，因此有了KV cache，而没有Q cache。这部分大家可以自己公式推导一下，也可以看这位答主的回答(1 条消息) 为什么加速LLM推断有KV Cache而没有Q Cache？ - 知乎。

KV cache必须存储在物理内存连续的一段中，这样存储，会在内存中产生很多碎片，无法高效利用内存资源。传统的KV cache会造成内存的三种浪费，第一是为当前request保留了但还没使用，未来会用到的内存；第二是内部碎片，为当前request保留但从来未使用；第三是外部碎片，由于KV cache连续存储于内存中，因此各个request之间存在未被使用的内存。下图中可以清楚看到各个浪费的部分，图中有两个request。三类浪费用红色标注，分别是reserved、internal fragmentation、external fragmentation。

PagedAttention

鉴于KV cache对内存的利用率过低，浪费极大。作者参考操作系统中虚拟内存的分页机制，提出了PagedAttention。

PagedAttention原理

PagedAttention的核心思想如下图所示，将物理内存分块，每个块大小固定，物理块与Logical KV block块大小一致。Logical KV block通过Block Table映射到对应的物理内存。Logical KV block记录了Logical KV block对应的物理内存编号，以及当前Logical KV block填充了几个token。图中Logical KV block的block0对应物理内存的bLock7，前期Logical KV block已有4个token，Logical KV block中的BLock1对应物理内存的Block1，当前已填充了4个token，有一个token待写入。从图中可以看出，KV cache再也不必连续存储，而是可以分散存在物理内存中不同区域。提高了内存利用率，从而可以同时处理多个request，增大了吞吐量。

下图是同时处理两个request的情形，token会从左到右填充Logical KV block，一个block填满后，再选择新的block填充，一个request完成后，会释放相应的物理内存块。

针对前缀共享的场景，例如系统提示词，如下图所示。vLLM会缓存共同前缀对应的KV。当处理不同的request时，只计算任务输入的KV，共同前缀对应的KV直接从物理内存中读取。

不同采样算法下的运用

下面来看PagedAttention对其他采样方法是如何支持的。

Parallel Sampling

并行采样的场景下，输入一个prompt会生成多个回答。采样A1和采样A2相同的部分block0，只会在物理内存中存在一份，对应物理block7。同一个物理block会被多个逻辑block使用，由此引入了引用计数，物理内存中Block7的引用计数为2，表示该物理block被两个逻辑block所使用。A1和A2的逻辑block1，前三个token相同。在生成第四个token之前，A1和A2的逻辑block1会映射到物理block1，因为两者生成的token完全相同，此时物理block1的引用计数为2，当A1和A2生成各自的第4个token时，生成结果不一致了。PagedAttention采用copy-on-write（写时复制）策略，将物理block1的内容复制到block3，随后block1的引用计数减1，A1新产生的token写入物理block3，A2新产生的token写入物理block1。写时复制策略避免了不必要的内存分配，只有在采样产生不同时才会分配新的物理内存块。

Beam Search

Beam Search采样会选取top-k个候选结果。下图中，k为4。共有4个候选序列，其中block0为prompt，被4个候选序列所共享。同样，block0在物理内存中只存在一份。在图中的虚线之前，每个序列都使用了4个逻辑块。虚线后，开始进行剪枝。block5，block2，block4，block8不再被使用，引用计数变为0，对应的物理内存被释放。同时，为block9，block10，block11，block12分配物理block。得到最终序列后，可以看出，block0，block1，block3被四个序列所共享。block6被第一个和第二个序列共享，block7被第三个和第四个序列共享。

在之前的LLM服务系统中，通常存在KV cache的冗余复制。例如在生成第二个序列（block0-1-3-6-10）时，图中的虚线之前。需要将第一个序列的KV cache进行复制，才能继续第二个序列的生成。不同分支之间的KV cache无法共享。这造成内存的浪费和低效使用。而vLLM则提供了多个分支之间的共享，通过PagedAttention实现，同时采用copy-on-write策略，只有在生成token不一致时，才会分配新内存块。
